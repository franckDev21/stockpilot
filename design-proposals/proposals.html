Design · Affichage multi-paiements par commande fournisseur
Branche : feature/payment-columns-inline · 3 options
À soumettre au client
Contexte : Une commande fournisseur peut avoir plusieurs paiements (avances + solde). Le client veut voir tous les paiements déjà effectués directement dans le tableau, avec pour chaque paiement : le montant, le type (Avance / Solde / Complet), une note, le reste après ce paiement, la date et l'heure.

Exemple d'une commande à 8 850 000 FCFA avec 3 paiements : Avance 1 : 2 000 000 Avance 2 : 3 425 000 Solde : 3 425 000 → Total soldé ✓
🅐 Paiements en sous-lignes
Chaque paiement a sa propre ligne sous les produits, dans le même tableau. Running balance visible. Vision comptable complète.
🅑 Mini-tableau paiements
Les produits s'affichent normalement. Un mini-tableau de paiements apparaît juste en dessous, toujours visible, avec toutes les transactions.
🅒 Colonne carte paiement
Une colonne dédiée à droite affiche une carte récapitulative avec tous les paiements listés + barre de progression. Très moderne.
Option A
Paiements en sous-lignes dans le tableau principal
Après les lignes produit de chaque commande, une section "Paiements" liste chaque transaction sur sa propre ligne avec le solde cumulatif.

💡 Recommandation finale

Avec plusieurs paiements par commande, Option B est la meilleure : le mini-tableau de paiements est toujours visible, chaque transaction est clairement listée avec son solde cumulatif, et le bouton "+ Ajouter" est intuitif. Option A convient mieux si le client veut une vue comptable stricte dans un seul tableau. Option C est idéale pour une app mobile ou un tableau de bord épuré.

→ Soumettez au client, puis confirmez le choix pour commencer le développement sur la branche feature/payment-columns-inline.
